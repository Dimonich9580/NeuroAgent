## 3. Риски

- **llama.cpp API быстро меняется.** Закреплён конкретный тег; JNI-слой изолирован в одном файле.
- **Ограничения Android на AccessibilityService** (OEM-прошивки могут отключать сервис). Документируется в README.
- **EncryptedSharedPreferences помечен deprecated** в security-crypto. Миграция на Tink/DataStore — в backlog.
- **Reproducible builds** ломаются от версии JDK/AGP и от путей сборки. Фиксируются версии JDK 17 и AGP, используется `--no-daemon`.
- **Shell-команды, выполняемые LLM,** — основной риск безопасности. Смягчается: отдельное включаемое разрешение, таймауты, журнал.

## 5. Результаты проверки (фактические)

Среда: песочница, 2 vCPU, 2 ГБ RAM, JDK 17, Gradle 8.10.2, Android SDK 35 / NDK 27.2.12479018 / CMake 3.22.1, Kotlin 2.0.21, llama.cpp `b11514` (`de7fa0a`).

|---|---|

| Юнит-тесты модуля `:app` (`testReleaseUnitTest`) | ✅ 11/11 (AgentLoop 3, SSE 2, аккумулятор 2, LocalToolCallParser 2, OpenAiClient с MockWebServer 2) |
| JNI-мост `neuro_llama_jni.cpp` против реальных заголовков `llama.h` (`g++ -fsyntax-only -Wall -Wextra`) | ✅ без ошибок и предупреждений |
| Аудит зависимостей `scripts/check_no_proprietary.sh` | ✅ AUDIT PASSED |
| Нативная сборка llama.cpp через NDK/CMake и линковка `libneuro_llama.so` | ⬜ **не завершена**: на 2 ГБ RAM сборка упирается в память (OOM, зависание песочницы) |

Найдено и исправлено при проверке: неверный путь к llama.cpp в CMake; отсутствующая иконка launcher; неверный импорт `padding`; неверное имя API `rememberLauncherForActivityResult`; импорт `LlmHttpException` в тесте; дедлок чтения stdout/stderr в `ShizukuManager.exec`; `awaitClose` в потоке локальной модели (поток не завершался бы).

Ограничение CI: `.github/workflows/reproducible.yml` ожидает обычный раннер GitHub (4 vCPU / 16 ГБ), на котором нативная сборка проходит. Пункт «нативная сборка» надо закрыть на таком раннере или на машине разработчика.

## 9. Результаты последнего прохода (воспроизводимость и APK)

Изменения: в `app/src/main/cpp/CMakeLists.txt` добавлены `-ffile-prefix-map` и `-fdebug-prefix-map` для `CMAKE_SOURCE_DIR` и `CMAKE_BINARY_DIR` (не `CMAKE_CURRENT_BINARY_DIR`, чтобы покрыть подпроект llama.cpp), отключён RPATH. `gradle.properties` приведён к одному набору ключей (без дублей): `-Xmx1200m`, `daemon=false`, `workers.max=1`, `parallel=false`, `kotlin.compiler.execution.strategy=in-process`.

| Проверка | Результат |
|---|---|
| `libneuro_llama.so` (arm64), сборка #1 и сборка #2 после очистки в том же каталоге | ✅ **побайтно одинаковы**, SHA-256 `a5f1fecd…21ad2` |
| Debug APK с готовой `.so` (CMake в Gradle не участвует), сборка #1 | ✅ собран, 61 МБ, содержит `classes.dex` и `lib/arm64-v8a/libneuro_llama.so` |
| Debug APK, повторная сборка после `clean` в том же каталоге (2 попытки) | ❌ демон Gradle убит системой при `mergeExtDexDebug` (нехватка памяти песочницы) |
| Воспроизводимость APK | ⬜ не подтверждена |
| Юнит-тесты | ✅ 11/11 (прогон на предыдущем этапе, после последних изменений кода не перепрогонялся) |
| Устройство | ⬜ не проверялось |

Вывод: нативная библиотека воспроизводима на уровне байтов при сборке в одном каталоге. Для APK проверка воспроизводимости на этой машине невозможна из-за памяти: второй билд после очистки стабильно убивается. Первый APK проверен по содержимому. Файл лежит в `~/.cache/nbuild/apk_build1.apk`, он не скопирован в рабочее пространство, потому что собран из копии с готовой `.so`, а не из репозитория с CMake.

Следующий шаг: CI (`.github/workflows/reproducible.yml`). Там надо исправить вторую сборку, чтобы она шла в том же пути, а не в `/tmp/rebuild-check`, иначе проверка сравнит разные каталоги.
